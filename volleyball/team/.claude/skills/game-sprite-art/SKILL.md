# Графика персонажей и игры (аниме-спорт)

Используй, когда задача — сделать героев, анимации, заставки, арену или интерфейс красивее.

## 1. Сначала — облик (character-designer)
- Источник правды: docs/characters.md (силуэт, причёска, лицо, цвета hex, аксессуар, поза, титул заставки).
- Только ОРИГИНАЛЬНЫЕ персонажи: никаких узнаваемых героев, причёсок, формы, имён и сюжетов из чужих аниме, манги и игр. Если описание складывается в известного героя — меняй силуэт.
- Каждый герой узнаётся по силуэту в 40 px высоты: причёска + рост + одна яркая деталь.

## 2. Два пути рисования
**A. Кодом (по умолчанию, d_chars.js)**
- Контур переменной толщины (голова ×1.5, торс ×1.35, дальняя рука тоньше), сел-шейдинг: базовый тон + тень + блик.
- Лица: крупные глаза с двумя бликами, брови передают эмоцию (приём — собранность, атака — ярость, очко — радость).
- Позы с линией действия: замах с прогибом, хлёст рукой, прыжок с поджатыми ногами, низкая стойка приёма, нырок.
- Лимит: ≤ 35 заливок на игрока за кадр, без shadowBlur/filter в кадре; тяжёлое — в offscreen-кэш.

**B. Спрайты (когда нужен «нарисованный художником» уровень)**
- Генерация: плагин SpriteCook (если подключён) или другой генератор изображений — промпт строится из docs/characters.md, стиль «clean anime sports, cel shading, bold outline», вид сбоку, прозрачный фон.
- Набор кадров на героя: стойка, бег (6), приём (3), пас (3), прыжок (2), удар (4), блок (2), радость (3). Одинаковый масштаб и точка опоры (ступни) во всех кадрах.
- Склейка в атлас PNG ≤ 1024×1024 на команду, встраивание в HTML как base64 (assets/*.b64 → плейсхолдер в build.py). Внешних URL картинок в игре быть не должно.
- Рисование: drawImage кадра атласа по состоянию позы; форма соперников — перекраска через отдельный атлас, не filter.
- Сетевой код не трогать: гость получает позы по PF и выбирает кадр по тем же числам.

## 3. Заставки и HUD (ui-hud-designer)
- Cut-in: диагональная плашка, полосы скорости, портрет, имя крупно, «прозвище · роль · №», титул удара с ударом масштаба. Пререндер, без shadowBlur в кадре.
- Табло «как в трансляции»: счёт с анимацией, подача, «до N».

## 4. Проверка перед публикацией
1. `python3 tools/build.py`
2. Скриншоты Playwright 844×390 и 667×375: покой, приём, атака, заставка (смотреть самому, ≤ 5).
3. `node tools/bot_test.js`, `node tools/local2_test.js`, `node tools/net_test.js`, `node tools/mq_test.js` — «NO ERRORS».
4. `node tools/perf_test.js 6` на свободной машине, 2–3 замера; не хуже базового больше чем на 10%.
5. code-reviewer — ревью, затем PR в main.
