# Волейбол «№4 × №10» — регламент команды агентов

Браузерная игра «волейбол 3 на 3» в одном HTML-файле: canvas 2D, без библиотек, для телефона в горизонтальной ориентации.

## Устройство проекта
| Файл | Что внутри | Владелец |
|---|---|---|
| src/a_html.html | разметка, стили, меню, кнопки | ui-hud-designer |
| src/b_core.js | константы, форма и внешность, звук, физика мяча, касания, подача, очки | gameplay-engineer |
| src/c_ai.js | ИИ команд, симуляция кадра, ввод игрока, эффекты по времени | gameplay-engineer |
| src/d_chars.js | позы, анимация, скелет, рисование игроков и мяча | character-artist |
| src/e_scene.js | арена, пол, сетка, камера (arena-artist); табло, баннеры, заставка после очка (ui-hud-designer) | два владельца |
| src/f_ui.js | превью в меню, экраны, управление, главный цикл | ui-hud-designer |
| assets/*.b64 | фото команды и портреты №4, №10 (base64) | никто не меняет без запроса |
| tools/ | build.py, bot_test.js, perf_test.js | release-builder, qa-tester |
| docs/story.md, docs/characters.md | библия истории и лист персонажей | story-writer, character-designer |

Сборка: `python3 tools/build.py` → `dist/volleyball.html`. Тесты: `node tools/bot_test.js`, `node tools/perf_test.js 6` (нужны Node и Playwright с Chromium).

## Кто на какой модели
| Категория | Модель | Агенты | Почему |
|---|---|---|---|
| Планирование и архитектура | Opus | game-director | редкие, но самые сложные решения: план, баланс, разбор трудных багов |
| Код средней сложности | Sonnet | gameplay-engineer, character-artist, arena-artist, ui-hud-designer, perf-optimizer, code-reviewer | основная работа: нужна аккуратность, но не максимальная модель |
| Сеть и онлайн | Sonnet | network-engineer | онлайн между странами: серверы, переподключение, задержка |
| Творческие тексты и дизайн | Sonnet | story-writer, character-designer | история, реплики, облик героев: нужен вкус, а не максимальная модель |
| Рутина | Haiku | qa-tester, release-builder, vfx-audio, copywriter-ru | команды по чек-листу, короткие точечные правки |

Основную сессию запускай на Sonnet. Директора на Opus зови только для крупных задач, мелкую правку отдавай сразу нужному агенту.

## Порядок работы
1. Крупная задача: game-director составляет план (до 8 пунктов) → основная сессия раздаёт пункты агентам. Независимые пункты запускаются параллельно.
2. Мелкая задача: сразу владельцу файла.
3. После каждой правки: release-builder → qa-tester. Перед публикацией — code-reviewer.
4. Задача закрыта, только когда bot_test пишет «over» и «NO ERRORS».

## Экономия токенов
- Агент читает только свои файлы и только нужные куски (Grep + Read с offset/limit).
- Правки точечные (Edit), а не переписывание файлов.
- Отчёты короткие (до 8 строк), без кода. Основная сессия не пересказывает отчёты пользователю целиком.
- Скриншоты смотрит только qa-tester, и не больше 3 за проверку.
- Не запускать агента «на всякий случай»: если правка в одну строку, её делает основная сессия сама.

## Герои (утверждены владельцем игры)
- №10 Рэй «Гром» Кадзама — нападающий; №9 Арис «Дирижёр» Мори — связующий; №4 Дан «Якорь» Ивасэ — либеро, обожает труд.
- Сквозная история: трое проходят через многое и в итоге становятся лучшими. Герои и сюжет — только свои, без заимствований из чужих аниме и манги.

## Жёсткие правила проекта
- Одно исключение в render()/update() не должно останавливать игру: главный цикл ловит ошибки и показывает плашку.
- Шрифты грузятся только скриптом, не через `<link>` в разметке: иначе при плохой сети игра не запускается.
- Никаких внешних картинок и звуков: всё рисуется кодом, звуки синтезируются.
- Не рисовать узнаваемых персонажей, логотипы и названия из чужих игр и аниме. Стиль «как спортивная аниме-игра» — можно, копии — нельзя.
- Фото команды — личные данные пользователя: не выкладывать никуда, кроме его собственной игры.
